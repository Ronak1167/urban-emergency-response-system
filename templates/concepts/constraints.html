DBMS Concept Visualizer 5

Integrity Constraints Violation Testing Sandbox

Demonstrating live DBMS enforcement of Referential Integrity (Foreign Keys), Domain Integrity (CHECK), and Entity Integrity (UNIQUE).

Visualizer Hub
Faculty Demonstration Guide: In DBMS lab evaluations, professors frequently ask: "What happens if a user tries to enter a patient age of -5, or inserts an emergency referencing an invalid patient ID?" Use this sandbox to fire intentional violation queries. The live database engine will intercept them and return exact rejection errors, proving constraint integrity!
Referential Integrity TEST 1

Foreign Key Constraint Violation

Attempt to insert an EMERGENCY referencing a non-existent patient_id = 99999.

INSERT INTO EMERGENCY (patient_id, ...)
VALUES (99999, 1, 1, 5, 'Reported');
Enforced by: FOREIGN KEY (patient_id) REFERENCES PATIENT(patient_id)
Domain Integrity TEST 2

CHECK Constraint Violation (Age Boundary)

Attempt to insert a PATIENT with negative age = -8.

INSERT INTO PATIENT (name, age, ...)
VALUES ('Invalid Age', -8, 'Male', ...);
Enforced by: CHECK (age > 0 AND age <= 125)
Domain Integrity TEST 3

CHECK Constraint Violation (Severity Out of Bounds)

Attempt to insert an EMERGENCY with clinical severity = 9 (allowed 1 to 5).

INSERT INTO EMERGENCY (..., severity, ...)
VALUES (..., 9, 'Reported');
Enforced by: CHECK (severity BETWEEN 1 AND 5)
Key Integrity TEST 4

UNIQUE Constraint Violation (Vehicle Number)

Attempt to insert duplicate ambulance registration number 'UP-16-AM-1001'.

INSERT INTO AMBULANCE (vehicle_no, ...)
VALUES ('UP-16-AM-1001', 'ALS', ...);
Enforced by: vehicle_no TEXT NOT NULL UNIQUE
