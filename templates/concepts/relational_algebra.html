Case Study 1: High-Severity Emergency Dispatch Dossier

Natural Join across 5 Relations: Emergency, Patient, Type, Location, Ambulance

5-Table Relational Join
Formal Relational Algebra Expression:
Πemergency_id, patient_name, vehicle_no, zone_area ( σseverity ≥ 4 ( EMERGENCY ⋈ PATIENT ⋈ LOCATION ⋈ RESOURCE_ALLOCATION ⋈ AMBULANCE ) )

Query Optimizer Execution Plan (EXPLAIN QUERY PLAN):

• SCAN EMERGENCY (Filters severity ≥ 4)
• SEARCH PATIENT USING INTEGER PRIMARY KEY (patient_id=?)
• SEARCH LOCATION USING INTEGER PRIMARY KEY (location_id=?)
• SCAN RESOURCE_ALLOCATION LEFT JOIN (emergency_id=?)
• SEARCH AMBULANCE USING INTEGER PRIMARY KEY (ambulance_id=?)

Notice how the SQLite optimizer automatically uses the Primary Key B-Tree index lookup (SEARCH ... USING INTEGER PRIMARY KEY) for $O(1)$ fast joins!

Case Study 2: Correlated Scalar Subquery for ICU Capacity

Compares individual hospital available ICU beds against the global city-wide average.

Correlated Subquery
Formal Relational Algebra with Aggregation:
Πhospital_name, vacant_icu ( σvacant_icu > γavg(vacant)(BED) ( HOSPITAL ⋈ DEPARTMENT ⋈ BED ) )

Query Optimizer Execution Plan (EXPLAIN QUERY PLAN):

• SCAN HOSPITAL
• CORRELATED SCALAR SUBQUERY 1: SCAN DEPARTMENT + BED WHERE hospital_id = outer.hospital_id
• SCALAR SUBQUERY 2: SCAN BED → AGGREGATE (AVG)

The correlated subquery re-evaluates for every outer hospital tuple, while the global average subquery is cached once.
