## 📌 Project Overview
The **Urban Emergency Response & Resource Allocation System** is an end-to-end relational database solution designed to eliminate coordination bottlenecks among emergency callers (112 helpline), dispatch operators, paramedic ambulance fleets, and receiving hospitals.

Built in strict compliance with **Third Normal Form (3NF)**, the system features:
- **ACID-Compliant Transactional Dispatch Engine**: Atomically matches incoming incidents with eligible ambulances (BLS/ALS) and reserves vacant hospital beds (ICU/General) without race conditions.
- **Automated Database Triggers**: Captures every state transition in real-time into an immutable `EMERGENCY_STATUS_HISTORY` audit trail.
- **Analytical SQL Views & Reporting**: Real-time fleet readiness, live hospital bed occupancy, and response latency analytics.
- **Zero-Friction Execution**: Runs out-of-the-box on standard Python with built-in SQLite and a lightweight Flask dashboard (no heavy external database server setup required).

### 1. Relational Entities (Normalized to 3NF)
1. `LOCATION` (location_id [PK], address_line, zone_area, landmark, postal_code, city_district)
2. `PATIENT` (patient_id [PK], name, age, gender, contact_phone, blood_group, triage_medical_notes)
3. `EMERGENCY_TYPE` (type_id [PK], type_name, description, severity_default, priority_rank)
4. `EMERGENCY` (emergency_id [PK], patient_id [FK], type_id [FK], location_id [FK], reported_time, severity, status)
5. `AMBULANCE` (ambulance_id [PK], vehicle_no [UNIQUE], type [BLS/ALS], operational_status, base_station)
6. `EQUIPMENT` (equipment_id [PK], ambulance_id [FK], equipment_name, serial_no [UNIQUE], is_functional)
7. `HOSPITAL` (hospital_id [PK], location_id [FK], hospital_name, contact_phone, emergency_level, total_beds)
8. `DEPARTMENT` (dept_id [PK], hospital_id [FK], dept_name, total_capacity, head_doctor, contact_ext)
9. `BED` (bed_id [PK], dept_id [FK], bed_number, floor_no, bed_type [ICU/General], is_occupied)
10. `STAFF` (staff_id [PK], hospital_id [FK], ambulance_id [FK], full_name, role_type, license_no [UNIQUE], phone_no)
11. `RESOURCE_ALLOCATION` (allocation_id [PK], emergency_id [FK], ambulance_id [FK], hospital_id [FK], bed_id [FK], dispatch_time, arrival_time, status)
12. `EMERGENCY_STATUS_HISTORY` (history_id [PK], emergency_id [FK], status_state, changed_at, updated_by, remarks)

### 2. Normalization Justification
- **1NF**: Every column contains atomic values; repeating equipment groups are separated into a dedicated `EQUIPMENT` table linked via foreign key.
- **2NF**: No partial dependencies; all non-key attributes are fully functionally dependent on primary keys.
- **3NF**: Transitive dependencies eliminated; geographic data is factored into `LOCATION` rather than duplicated across `HOSPITAL` and `EMERGENCY`.

### 3. Database Triggers
- `trg_emergency_status_insert`: Automatically logs the initial intake state when a new emergency is reported.
- `trg_emergency_status_update`: Automatically logs every lifecycle transition (`Reported` &rarr; `Dispatched` &rarr; `In-Transit` &rarr; `Admitted` &rarr; `Resolved`) into `EMERGENCY_STATUS_HISTORY`.

### 4. ACID Transaction Workflow
```
[112 Incident Reported]
         │
         ▼
[BEGIN IMMEDIATE TRANSACTION]
         │
         ├── 1. Check Incident Eligibility (Status: 'Reported')
         ├── 2. Query Qualified Ambulance (ALS if Severity >= 4 with operational ventilator)
         ├── 3. Query Vacant Bed (ICU bed if Severity >= 4; General bed if Severity < 4)
         ├── 4. Update AMBULANCE: Set operational_status = 'Dispatched'
         ├── 5. Update BED: Set is_occupied = 1
         ├── 6. Insert RESOURCE_ALLOCATION record
         └── 7. Update EMERGENCY: Set status = 'Dispatched'
                   │
                   └── [TRIGGER FIRES: Logs to EMERGENCY_STATUS_HISTORY]
         │
         ▼
[COMMIT TRANSACTION] (Rolls back completely if ambulance or bed unavailable)
```
